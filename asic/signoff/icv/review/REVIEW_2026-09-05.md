## A. Findings, ranked by severity

### A1. ERROR (rule semantics, cannot be caught by compile): every `enclose()` call has its layers reversed

`sky130_beol.rs` section 6 (`-D BEOL_EXTRA`) writes `enclose(met1, via1, distance < 0.055, ...)`
and the same pattern for via2_4, m3_4, via3_4, m4_3, via4_4, m5_3 (7 rules), with the comment
"enclose(layer1, layer2, distance < d) reports where layer1 encloses layer2 by less than d".
`sky130_beol_min.rs` trailing comment and `SIV.md` section 2 skeleton ("`enclose(l1, l2, ...)  // l1
must enclose l2`") and section 3.2 table (`enclose(met1, mcon, < 0.03)`, `enclose(met1, via1, < 0.055)`,
`enclose(met2, via2, < 0.04)`, ...) state the same convention as fact, "quoted from icvrefman.pdf".

The reference manual says the opposite (icvrefman.pdf U-2022.12, enclose() page 479, identical wording on
the enclose_edge/enclose_error pages, text lines 20547-20550 of the pdftotext dump):

> layer1  Required. Specifies the **enclosed** input edge or polygon layer.
> layer2  Required. Specifies the **enclosing** edge or polygon layer against which the layer1 layer is checked.

Correct form for the deck's `m2.enclosing(via2, 0.04, euclidian)` is therefore
`enclose(via2, met2, distance < 0.04, extension = RADIAL)` -- via first, metal second. As written the
rules measure "how far met1 is enclosed by via1", which is geometrically meaningless here and would
either report nothing or report every metal edge near a via. Compile cannot detect it. The block is
labelled "unvalidated" in the runset, but SIV.md presents the convention as verified manual text.
Fix: swap the two layer arguments in all 7 calls and in the three documents.

### A2. ERROR (script): `run_icv_drc.sh` can never print its exit code, LICENSE DENIED guard, or LAYOUT_ERRORS head on a failing run

`set -euo pipefail` (line 35) plus

```
"${CMD[@]}" 2>&1 | tee icv_stdout.log
rc=${PIPESTATUS[0]}
```

With `pipefail`, the pipeline's status is icv's status; with `-e` a non-zero status aborts the script
at that line. So on the one scenario the script was written for (exit 67, license denied) it dies
silently after tee and none of the following lines run: `echo "# icv exit code"`, the `grep -q "License
denied"` guard, the `*.LAYOUT_ERRORS` head. Reproduced with `review/pipefail_test.sh` (same three lines
with a stub that exits 67): output is only the stub's own text, script rc=67, no `#` lines.
SIV.md section 7 ("prints a LICENSE DENIED line instead of retrying ... dry run OK") and README
("flags 'License denied' instead of retrying") claim this was verified; it cannot have been -- the
dry-run path exits before the pipeline, and the real run's `icv_stdout.log` (runs/20260905_synth_test)
contains only icv's own text. Fix: `"${CMD[@]}" 2>&1 | tee icv_stdout.log || true` then read
`PIPESTATUS`, or wrap in `set +e` / `if ! ...`.

Lesser script issues (not bugs in the exec path): the printed command uses `${CMD[*]}` unquoted, so
`-c "Cache Top"` or `-c '*'` print as `-c Cache Top` / `-c *` -- not copy-paste safe (the executed
`"${CMD[@]}"` is fine); default `run_dir` is `$PWD/icv_run_<ts>`, whereas README says never run
outside `icv/runs/`. Sourcing `/apps/settings` under `set -u` works (tested).

## I. Verdict

The numeric content is sound: all 36 width/spacing/size/area values and all layer/datatype numbers in
both DRC runsets and the LVS runset match the PDK deck and tech files, the deck line citations are
accurate, the synthetic fixture and its KLayout reference counts reproduce exactly, the license-wall
diagnosis (T-2022.03 asks for Elite/Base keys, server has only Apex, `-lic_apex` unknown to the binary)
is correct and reproducible, and the CDL/GDS/Verilog facts in SIV_LVS.md check out to the unit. The
deliverables are **not trustworthy as-is** in three places: (1) every `enclose()` rule has its enclosed
and enclosing layers swapped, and the three documents teach the wrong convention as manual-verified
fact -- this will silently produce wrong results the day the BEOL_EXTRA block runs; (2) `run_icv_drc.sh`
cannot execute its own failure handling (`set -e` + `pipefail` around `icv | tee`), so the
"license-denied guard verified" claim is false; (3) a handful of doc statements are wrong (`-dp`
option, top-cell name in SIV.md, "no other ICV installed", Magic line numbers, diode count). Fix A1, A2,
A4 and A6 before anyone builds on this; the rest are doc corrections. The 32-rule default block of
`sky130_beol.rs` and the 4-rule `sky130_beol_min.rs` can be used as they stand once a license works,
with the documented huge-metal and item-count caveats.
